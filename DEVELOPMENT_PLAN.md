# План разработки Mini Factory

Этот документ описывает пошаговый план разработки проекта Mini Factory от пустого Unity-проекта до сдачи согласно техническому заданию.

## 1. Настройка проекта

- Создать новый Unity-проект (версия 6000.3.22f1) с поддержкой Android.
- Настроить структуру папок проекта:
  - `Assets/_Project/Scripts`
  - `Assets/_Project/Configs`
  - `Assets/_Project/Prefabs`
  - `Assets/_Project/Scenes`
  - `Assets/_Project/UI`
  - `Assets/_Project/Tests/EditMode`
  - `Assets/_Project/Tests/PlayMode`
- Настроить .asmdef файлы для разделения кода:
  - `Game.Runtime.asmdef`
  - `Game.Editor.asmdef`
  - `Game.Tests.EditMode.asmdef`
  - `Game.Tests.PlayMode.asmdef`
- Добавить корректный .gitignore для Unity, исключающий временные файлы и build artifacts.
- Инициализировать Git-репозиторий и настроить GitFlow.
- Создать первый commit с базовой структурой.

## 2. Domain-слой (чистый C#)

Реализовать ядро бизнес-логики игры, не зависящее от Unity:

- `MachineModel`: модель данных для производственной машины (состояние, уровень, производительность и т.д.).
- `CostCalculator`: сервис для расчета стоимости открытия и улучшения машин.
- `EconomyService`: сервис для управления игровой валютой и производительностью.
- `BoostService`: сервис для управления временным ускорением производства.
- `OfflineProgressCalculator`: сервис для расчета дохода за время offline.
- Все классы должны быть легко тестируемыми и не наследоваться от MonoBehaviour.

## 3. Config-слой

Создать систему конфигурации, отделенную от игровой логики:

- Интерфейс `IGameConfig` для доступа к параметрам игры.
- `GameConfigSO`: ScriptableObject, реализующий `IGameConfig`.
- Конфигурация должна включать:
  - Параметры машин (стоимость, производительность и т.д.)
  - Стоимость открытия и улучшения машин
  - Параметры Boost (длительность, множитель)
  - Максимальное время offline-дохода

## 4. Services-слой

Реализовать сервисы, скрывающие детали внешних SDK:

- `IStorageService` и `JsonFileStorageService`: для сохранения и загрузки данных игры.
- `IAnalyticsProvider` и `ConsoleAnalyticsProvider`: для отправки аналитических событий.
- `IIAPService` и `UnityIAPService`: для работы с Unity IAP (с использованием Fake Store).
- Все сервисы должны быть за интерфейсами, чтобы игровая логика не зависела от конкретных реализаций.

## 5. Persistence

Создать систему сохранения прогресса игрока:

- `SaveData`: структура данных для хранения состояния игры.
- Реализовать логику сохранения и загрузки с использованием `IStorageService`.
- Убедиться, что данные корректно сохраняются и восстанавливаются между запусками.

## 6. Presentation-слой

Создать пользовательский интерфейс и связать его с доменной логикой:

- UI-элементы для отображения:
  - Баланса игрока
  - Состояния и уровня машин
  - Цен и кнопок действий
  - Состояния Boost
- `MachineView`: компонент для отображения одной машины.
- `FactoryView`: компонент для управления всеми машинами.
- `BoostView`: компонент для управления Boost.
- `GameBootstrap`: MonoBehaviour для инициализации всех систем и сервисов при старте игры.
- Все MonoBehaviour-компоненты должны быть тонкими адаптерами, вызывающими методы Domain и Services.

## 7. Tests

Написать unit-тесты для проверки ключевой логики:

- Минимум 3 unit-теста в `Assets/_Project/Tests/EditMode/`:
  - Расчет стоимости улучшения машины
  - Расчет offline-дохода с учетом лимита времени
  - Работа и применение Boost
- Тесты должны проверять логику Domain-слоя и быть независимыми от Unity.

## 8. Documentation

Создать документацию для проекта:

- `README.md`:
  - Инструкции по запуску и сборке под Android
  - Описание основных систем и архитектурных решений

  - Известные ограничения или незавершенные части

  - Задачи, переданные AI

  - Что сделано самостоятельно

  - Ошибки или спорные решения AI
